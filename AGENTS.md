# YAR Agency — project instructions

## Intent
Build a Ukrainian independent music agency presentation for artists, musicians, bands and their managers, based on actual user-supplied branding and photographs. Maintain the concept in docs/DIRECTION.md. This prototype is for design review, not approved company messaging.

## Stack and commands
React 19 + Vite. `npm ci`, `npm run dev`, `npm run build`, `npm run preview`. Run `npm run standalone` after a build to generate dist/preview.html. Vercel configuration is included. Node 24, npm and package-lock.json are the canonical toolchain. GitHub repository: Zoreslaw/yar-agency. Deployment configuration is ready for Vercel; no backend is connected.

## Visual contract
- Palette: ink #1D223D, burgundy #991A1E, cream #FFFBD4, yellow #FFCC00.
- Keep the original YAR mark. User PNG is cropped only by SVG viewport; never replace it with a text approximation.
- Full-width monochrome video with cream title overlay and a fixed transparent header; header gains a dark translucent blur after 24px scroll. Photographic sequence and collaboration section follow.
- No strobing videos, flashing lights, reversed human movement, or ghosted crossfades. Existing montage uses intentional cuts.
- Favor the original brand mark and original photographs. Headings have varied scale and moderate weight. Do not introduce a generic feature-card grid, gradients unrelated to the materials, decorative counters, or fabricated awards.
- Manrope is a temporary Cyrillic alternative until licensed Gotham files are supplied. Keep fonts local.

## Content and interaction
- No invented artists, event dates, company history, numbers, client names, addresses, emails or testimonials.
- User confirmed the existing gallery belongs to the continuing wuha collaboration example. Preserve all photos; do not invent case-study results, dates or credits. The team reference photo is explicitly labelled stock, not Sofia and Vika.
- Draft Ukrainian copy is marked in the footer. Confirm company scope before turning proposals into claims.
- Brief form downloads locally; never pretend it submitted. Email yars.agency@gmail.com and Instagram @yar_agcy are supplied in the service PDF and may be linked. Do not add form submission without a real integration.
- Services are sourced from the supplied service PDF; package prices are omitted per user instruction. Scope and cost are agreed individually. Two formats: specific tasks/concerts/trips and continuing artist collaboration.
- Preserve keyboard focus, dialog Escape, meaningful alt text, reduced-motion behavior and video pause.

## Assets and QA
Originals in source-assets/ and Downloads must remain unchanged. Responsive derivatives in public/media are generated by scripts/optimize-assets.mjs; preserve source provenance in docs/ASSETS.md.
After layout changes, inspect the actual browser at desktop and mobile widths (including 320px); check text clipping as well as horizontal document overflow. Validate relevant interactions and run npm run build. Keep QA screenshots out of Git.

## Work with this repository
- Read docs/HANDOFF.md for current state, docs/DIRECTION.md for design intent, and docs/ASSETS.md before touching media.
- Implement only the requested scope. Do not refactor the whole page or add dependencies to solve a small visual change.
- Work on a descriptive feature branch for subsequent changes. Run `npm run check` and `npm run build` before pushing. Changes to dependencies must update package-lock.json.
- Vercel builds from the repository root. `main` is the production branch once Vercel is connected; feature branches/PRs can receive preview deployments. Do not claim deployment is configured on the account merely because vercel.json exists.
- Do not commit dist, node_modules, original photo copies, QA captures, environment files or credentials. Rendered media in public is required for clean builds.
- The mouth effect is deliberately punk: broken silhouette, independent slab compression/translation, missing ink, hard kicks. Preserve pause, reduced motion, visibility guards, transparent padding. Do not replace it with a smooth wave without user direction.
- The user owns and authors this project. Never present an AI tool or agent as author, co-author, contributor, maintainer or collaborator in commits, PRs, release notes, README files, site credits or other project-facing material. Never add Co-authored-by trailers, bot identities, generated-by signatures or promotional tool credits. Use the user's configured Git identity. Use neutral descriptive branch names without agent/tool branding unless explicitly requested. Preserve required third-party licenses and factual asset provenance.
- After changes, describe actual behavior, validation and remaining limitations. Do not invent successful checks or approved business copy.
